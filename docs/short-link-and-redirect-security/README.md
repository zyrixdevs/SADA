# Short Link and Redirect Security

**Catalogue module 38 of 49. Status: proposed specification only; not implemented or deployed.**

## Purpose

Resolve URL redirect chains in an isolated service and identify deceptive destination transitions.

## What it does

Normalize URL; apply SSRF and scheme checks; resolve using isolated egress proxy with redirect/time/byte caps; record each hop; compare reputation and destination; expire results.

## What it must never do

- It must not execute Discord moderation or configuration changes. Zyrix Bot remains the only Discord action boundary and rechecks local consent, permissions and role hierarchy.
- It must not treat a score, anomaly or single report as proof or punishment authority.
- It must not bypass guild opt-in, shared case/review, evidence, identity or audit contracts.

## Signals and workflow

**Inputs:** Submitted URL; DNS/HTTP redirect observations; TLS/domain metadata; scanner egress policy; domain reputation refs.

```mermaid
flowchart LR
 A[Authorized source event or advisory] --> B[Validate scope, version and consent]
 B --> C[Normalize and preserve provenance]
 C --> D[Module-owned analysis: Short Link and Redirect Security]
 D --> E[Versioned explainable finding]
 E --> F[Shared incident, case and review services]
 F --> G[Scoped advisory or Zyrix local decision]
 C --> H[Canonical audit and correction path]
```

Preserve raw submitted URL encrypted only when needed; canonicalize IDNA host, default ports and path safely; classify each hop; pin DNS answers per fetch and reject private/reserved ranges at every redirect.

## Ownership and integration

This module owns only domain-specific observations, snapshots, assessments and indicator references. It reuses canonical installation/consent, event inbox, incident/evidence, case/review, delivery/outbox and audit records. It does not create separate authentication, case management, evidence vault, reviewer quorum or audit systems.

Dependencies: [Scam and Phishing Intelligence](../scam-and-phishing-intelligence/README.md), [QR Code Threat Detection](../qr-code-threat-detection/README.md), External Threat Feed Intelligence..

## Security, privacy and limitations

Hard egress allow/deny policy, private IP block on every hop, no cookies/auth, bounded redirects/body/time, network isolation. Live resolution is time-dependent and may expose the scanner to malicious content; no page scripts, downloads, credentials or browser session.

Cross-guild sharing requires explicit purpose and permission. Missing, stale or inaccessible data is represented as unknown/partial. Corrections and revocations are versioned and propagate to pending deliveries.

## API and event contract

**Method:** `POST`. Proposed internal endpoint: `POST /v1/url-analysis/redirects`. It uses the shared `/v1` authentication and authorization model, guild scope from authenticated grants, request ID, schema version, idempotency key, bounded JSON payload, and shared error shape. The endpoint accepts observations or recommendations only; it does not execute Discord actions. A durable inbox receipt is returned only after commit. Duplicate key + same canonical body returns the original receipt; changed body returns `409`. Retry only transient `retryable=true` errors.
