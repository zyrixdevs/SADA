# 02 — Threat network architecture

**Status: proposed specification; not implemented.**

## Scope

This chapter defines the threat network architecture responsibility of Threat Intelligence Network. Correlate provenance-bearing security incidents across independently opted-in installations.

## Proposed technical contract

Boundary: Zyrix adapter validates consent and submits events; Rust Core owns this workflow; PostgreSQL is authoritative; API returns scoped projection; Zyrix alone performs Discord actions. Process: Validate independent source, add typed graph edges, evaluate provenance, route candidate links for review. Inputs: Authorized incidents, source-guild scope, event/evidence references, correction state, consent version. Output: Candidate typed relationships and scoped intelligence, never verdicts. Owned projections: incidents, relationship_edges, cases, case_links, audit_events Acceptance invariant: Duplicates from one source create one edge; reversal removes active support but retains audit history.

## Failure and safety behavior

One guild, installation, retry, or copied report never counts as several independent sources. Sybil reports, collusion, graph traversal leakage, evidence poisoning. Retry transient failures only with idempotency; reject permanent authorization/schema errors. Reconcile ambiguous external outcomes by request ID before retry. SADA outage cannot authorize a Discord action.
