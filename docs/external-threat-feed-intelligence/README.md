# External Threat Feed Intelligence

**Catalogue module 40 of 49. Status: proposed specification only; not implemented or deployed.**

## Purpose

Ingest trusted external threat indicators with provenance, freshness and correction tracking.

## What it does

Fetch via allowlisted egress; validate signature/schema/size; normalize indicator; dedupe source revision; quarantine invalid content; store provenance and expiry; publish only after configured validation/review.

## What it must never do

- It must not execute Discord moderation or configuration changes. Zyrix Bot remains the only Discord action boundary and rechecks local consent, permissions and role hierarchy.
- It must not treat a score, anomaly or single report as proof or punishment authority.
- It must not bypass guild opt-in, shared case/review, evidence, identity or audit contracts.

## Signals and workflow

**Inputs:** Feed identity/signature; indicator value/type; published/updated timestamps; confidence fields; license/use terms; STIX-like reference if approved.

```mermaid
flowchart LR
 A[Authorized source event or advisory] --> B[Validate scope, version and consent]
 B --> C[Normalize and preserve provenance]
 C --> D[Module-owned analysis: External Threat Feed Intelligence]
 D --> E[Versioned explainable finding]
 E --> F[Shared incident, case and review services]
 F --> G[Scoped advisory or Zyrix local decision]
 C --> H[Canonical audit and correction path]
```

Dedup key includes indicator type, canonical value and source revision; preserve provider assertion distinct from SADA assessment. Feed trust is policy metadata, not a score copied as truth.

## Ownership and integration

This module owns only domain-specific observations, snapshots, assessments and indicator references. It reuses canonical installation/consent, event inbox, incident/evidence, case/review, delivery/outbox and audit records. It does not create separate authentication, case management, evidence vault, reviewer quorum or audit systems.

Dependencies: [Threat Intelligence Network](../threat-intelligence-network/README.md), [Security Advisory Network](../security-advisory-network/README.md), [Scam and Phishing Intelligence](../scam-and-phishing-intelligence/README.md), [Malicious Attachment Intelligence](../malicious-attachment-intelligence/README.md), Supply Chain Intelligence..

## Security, privacy and limitations

Secret manager for feed creds; SSRF-safe allowlist; no arbitrary feed URLs; validate signed content; isolate parser; audit source changes. Feeds may be poisoned, stale, licensed restrictively or encode dangerous URLs; ingestion alone does not authorize guild alerts.

Cross-guild sharing requires explicit purpose and permission. Missing, stale or inaccessible data is represented as unknown/partial. Corrections and revocations are versioned and propagate to pending deliveries.

## API and event contract

**Method:** `POST`. Proposed internal endpoint: `POST /v1/threat-feeds/imports`. It uses the shared `/v1` authentication and authorization model, guild scope from authenticated grants, request ID, schema version, idempotency key, bounded JSON payload, and shared error shape. The endpoint accepts observations or recommendations only; it does not execute Discord actions. A durable inbox receipt is returned only after commit. Duplicate key + same canonical body returns the original receipt; changed body returns `409`. Retry only transient `retryable=true` errors.

Example request:
```json
{
  "schema_version": "1.0",
  "event_id": "018f0000-0000-7000-8000-000000000001",
  "source_guild_id": "123456789012345678",
  "occurred_at": "2026-11-16T10:00:00Z",
  "consent_version": "guild-consent-7",
  "correlation_id": "018f0000-0000-7000-8000-000000000003",
  "payload": { "observation_ref": "opaque-reference", "type": "module-specific" }
}
```

Example accepted response:
```json
{"event_id":"018f0000-0000-7000-8000-000000000001","receipt_id":"018f0000-0000-7000-8000-000000000004","status":"accepted","duplicate":false}
```
