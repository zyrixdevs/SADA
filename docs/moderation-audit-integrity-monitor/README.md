# Moderation Audit Integrity Monitor

**Catalogue module 34 of 49. Status: proposed specification only; not implemented or deployed.**

## Purpose

Reconcile expected moderation/configuration events with available audit records and preserve tamper-evident local history.

## What it does

Append event receipt; match expected action to audit record within bounded time; classify missing/duplicate/mismatch; build chained digest batches; expose reconciliation status and corrective events.

## What it must never do

- It must not execute Discord moderation or configuration changes. Zyrix Bot remains the only Discord action boundary and rechecks local consent, permissions and role hierarchy.
- It must not treat a score, anomaly or single report as proof or punishment authority.
- It must not bypass guild opt-in, shared case/review, evidence, identity or audit contracts.

## Signals and workflow

**Inputs:** Confirmed action receipts; Discord audit entry IDs; event times; actor attribution; source sequence/cursor; prior digest.

```mermaid
flowchart LR
 A[Authorized source event or advisory] --> B[Validate scope, version and consent]
 B --> C[Normalize and preserve provenance]
 C --> D[Module-owned analysis: Moderation Audit Integrity Monitor]
 D --> E[Versioned explainable finding]
 E --> F[Shared incident, case and review services]
 F --> G[Scoped advisory or Zyrix local decision]
 C --> H[Canonical audit and correction path]
```

Use explicit match keys and allowed time window; an unmatched item is pending/unknown before missing; digest chain detects alteration but not source truth.

## Ownership and integration

This module owns only domain-specific observations, snapshots, assessments and indicator references. It reuses canonical installation/consent, event inbox, incident/evidence, case/review, delivery/outbox and audit records. It does not create separate authentication, case management, evidence vault, reviewer quorum or audit systems.

Dependencies: [Incident Timeline](../incident-timeline/README.md), [Suspicious Admin Activity](../suspicious-admin-activity/README.md), [SADA Operator Activity Monitoring](../sada-operator-activity-monitoring/README.md), Shared Audit Standard..

## Security, privacy and limitations

Append-only privileges, periodic external digest anchoring considered later; protect audit query access; no secrets in digest metadata. Discord audit access/retention/permissions may be incomplete; SADA cannot promise completeness or detect deletion before capture.

Cross-guild sharing requires explicit purpose and permission. Missing, stale or inaccessible data is represented as unknown/partial. Corrections and revocations are versioned and propagate to pending deliveries.

## API and event contract

**Method:** `POST`. Proposed internal endpoint: `POST /v1/audit/reconciliation-events`. It uses the shared `/v1` authentication and authorization model, guild scope from authenticated grants, request ID, schema version, idempotency key, bounded JSON payload, and shared error shape. The endpoint accepts observations or recommendations only; it does not execute Discord actions. A durable inbox receipt is returned only after commit. Duplicate key + same canonical body returns the original receipt; changed body returns `409`. Retry only transient `retryable=true` errors.

Example request:
```json
{
  "schema_version": "1.0",
  "event_id": "018f0000-0000-7000-8000-000000000001",
  "source_guild_id": "123456789012345678",
  "occurred_at": "2026-11-16T10:00:00Z",
  "consent_version": "guild-consent-7",
  "correlation_id": "018f0000-0000-7000-8000-000000000003",
  "payload": { "observation_ref": "opaque-reference", "type": "module-specific" }
}
```

Example accepted response:
```json
{"event_id":"018f0000-0000-7000-8000-000000000001","receipt_id":"018f0000-0000-7000-8000-000000000004","status":"accepted","duplicate":false}
```
