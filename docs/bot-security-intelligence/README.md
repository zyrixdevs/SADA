# Bot Security Intelligence

**Catalogue module 20 of 49. Status: proposed specification only; not implemented or deployed.**

## Purpose

Share reviewed, provenance-bearing intelligence about bot identities, service compromise and abuse across opted-in guilds. It specializes the bot/integration domain on the existing Threat Intelligence Network graph.

## What it does

Normalize bot identity and event type; deduplicate by source event; correlate only same bot identity or typed integration evidence; create a candidate finding; route for review; distribute scoped advisory and corrections.

## What it must never do

- It must not execute Discord moderation or configuration changes. Zyrix Bot remains the only Discord action boundary and rechecks local consent, permissions and role hierarchy.
- It must not treat a score, anomaly or single report as proof or punishment authority.
- It must not bypass guild opt-in, shared case/review, evidence, identity or audit contracts.

## Signals and workflow

**Inputs:** Bot application ID; installation-scoped bot identity; permitted moderation/audit events; report and advisory references; source reliability snapshot.

```mermaid
flowchart LR
 A[Authorized source event or advisory] --> B[Validate scope, version and consent]
 B --> C[Normalize and preserve provenance]
 C --> D[Module-owned analysis: Bot Security Intelligence]
 D --> E[Versioned explainable finding]
 E --> F[Shared incident, case and review services]
 F --> G[Scoped advisory or Zyrix local decision]
 C --> H[Canonical audit and correction path]
```

Use typed indicators (application, publisher, behavior class) and versioned behavior windows. Repeated destructive actions can raise review priority only when independent guilds and provenance are explicit; no numeric threshold is approved.

## Ownership and integration

This module owns only domain-specific observations, snapshots, assessments and indicator references. It reuses canonical installation/consent, event inbox, incident/evidence, case/review, delivery/outbox and audit records. It does not create separate authentication, case management, evidence vault, reviewer quorum or audit systems.

Dependencies: [Threat Intelligence Network](../threat-intelligence-network/README.md), [Integration Supply Chain Intelligence](../integration-supply-chain-intelligence/README.md), [Bot Compromise Early Warning](../bot-compromise-early-warning/README.md), [Security Advisory Network](../security-advisory-network/README.md), Threat Intelligence API..

## Security, privacy and limitations

Scope bot observations to purpose/consent; redact guild-private context; no bot tokens or secrets; reject cross-tenant lookup without approved intelligence scope. A shared bot name/avatar is not identity; public bot listings and a single report are not proof. Discord metadata may be unavailable or stale.

Cross-guild sharing requires explicit purpose and permission. Missing, stale or inaccessible data is represented as unknown/partial. Corrections and revocations are versioned and propagate to pending deliveries.

## API and event contract

**Method:** `POST`. Proposed internal endpoint: `POST /v1/bot-security/observations`. It uses the shared `/v1` authentication and authorization model, guild scope from authenticated grants, request ID, schema version, idempotency key, bounded JSON payload, and shared error shape. The endpoint accepts observations or recommendations only; it does not execute Discord actions. A durable inbox receipt is returned only after commit. Duplicate key + same canonical body returns the original receipt; changed body returns `409`. Retry only transient `retryable=true` errors.

Example request:
```json
{
  "schema_version": "1.0",
  "event_id": "018f0000-0000-7000-8000-000000000001",
  "source_guild_id": "123456789012345678",
  "occurred_at": "2026-11-16T10:00:00Z",
  "consent_version": "guild-consent-7",
  "correlation_id": "018f0000-0000-7000-8000-000000000003",
  "payload": { "observation_ref": "opaque-reference", "type": "module-specific" }
}
```

Example accepted response:
```json
{"event_id":"018f0000-0000-7000-8000-000000000001","receipt_id":"018f0000-0000-7000-8000-000000000004","status":"accepted","duplicate":false}
```
